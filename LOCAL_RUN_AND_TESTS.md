## Шаг 1. Установить Python

1. Скачайте Python 3.12+ с [python.org](https://www.python.org/downloads/).
2. При установке **ОБЯЗАТЕЛЬНО** поставьте галочку ✅ **«Add Python to PATH»** (внизу окна установки).
3. Проверьте установку — откройте **командную строку** (Win+R → `cmd` → Enter) и введите:

```bash
python --version
```

Должно появиться что-то вроде `Python 3.12.4`. Если появилось — отлично, Python работает.

> ⚠️ Если пишет `python не является внутренней или внешней командой` — вы забыли галочку «Add to PATH». Переустановите Python с этой галочкой.

## Шаг 2. Получить 3 ключа

Боту нужны **три ключа**, без которых он не запустится.

### 2.1. Telegram-бот токен

1. Откройте в Telegram [@BotFather](https://t.me/BotFather)
2. Отправьте команду `/newbot`
3. Придумайте **имя** (например: `My Calendar Bot`) и **username** (например: `my_cal_bot`, обязательно заканчивается на `_bot`)
4. BotFather пришлёт токен вида:
   ```
   123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```
   **Скопируйте его и сохраните.**

**Узнать свой chat_id** (нужен, чтобы бот знал, кому отвечать):
1. Отправьте своему новому боту **любое сообщение** (например, «привет»)
2. Откройте в браузере ссылку, подставив свой токен:
   ```
   https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates
   ```
   Например: `https://api.telegram.org/bot123456789:AAExxx.../getUpdates`
3. В ответе найдите `"chat":{"id": 123456789}` — это и есть ваш `chat_id`. **Сохраните его.**

### 2.2. OpenAI API ключ

1. Зайдите на [platform.openai.com/api-keys](https://platform.openai.com/api-keys)
2. Нажмите **Create new secret key**
3. Скопируйте ключ `sk-...` (он показывается только один раз!)
4. **Обязательно пополните баланс**: Settings → Billing → Add payment. Без денег API не работает.
   - Для тестов хватит $5–10. Одно голосовое сообщение ≈ $0.01.

### 2.3. Google OAuth Client ID + Secret

Это самый длинный шаг, но нужно сделать его один раз.

1. Откройте [Google Cloud Console](https://console.cloud.google.com/)
2. Создайте новый проект: сверху в шапке → **выпадающий список** → **NEW PROJECT** → имя `calendar-bot` → Create
3. **Включите Calendar API:**
   - Левое меню → **APIs & Services → Library**
   - Поиск: `Google Calendar API` → откройте → **ENABLE**
4. **Настройте OAuth consent screen** (экран согласия):
   - Левое меню → **APIs & Services → OAuth consent screen**
   - User type: **External** → Create
   - Заполните обязательные поля: App name (`Calendar Bot`), User support email (ваш Gmail), Developer contact (ваш Gmail)
   - Нажмите **Save and Continue** до конца (Scopes можно пропустить, добавьте `.../auth/calendar` если спросит)
   - В разделе **Test users** → **+ ADD USERS** → добавьте свой Gmail → Save
5. **Создайте Credentials (ключи):**
   - Левое меню → **APIs & Services → Credentials**
   - **+ CREATE CREDENTIALS → OAuth client ID**
   - Application type: **Web application**
   - Name: `Calendar Bot Local`
   - **Authorized       redirect URIs** → **+ ADD URI** → вставьте:
     ```
     http://localhost
     ```
     (именно `http://localhost`, без порта и без слэша в конце)
   - **Create**
6. Появится окно с **Client ID** и **Client Secret**. Скопируйте оба.
   - Client ID выглядит как `123456789-xxxxx.apps.googleusercontent.com`
   - Client Secret выглядит как `GOCSPX-xxxxx`

🎉 Поздравляю, все три ключа готовы!

Эта команда скачает ~50 библиотек, **займет 2–5 минут**. Не прерывайте её.

> 💡 Если пишет «доступ запрещён» / «permission denied» — откройте консоль **от администратора** и повторите.

> 💡 Если интернет медленный и отваливается — повторите команду, pip докачает оставшееся.

```bash

```

Должно написать версию pytest (например `pytest 8.0.0`).

## Шаг 4. Настроить файл `.env`

Файл `.env` — это конфигурация, где хранятся ваши ключи. **Он никогда не попадает в git** (для безопасности).

### 4.1. Создать файл из примера

В папке проекта:

```bash
cp .env.example .env
```

(На Windows в cmd: `copy .env.example .env`)

### 4.2. Открыть `.env` и заполнить

Откройте файл `.env` в любом редакторе (Блокнот, VS Code, Notepad++) и заполните своими значениями:

```env
# === Telegram ===
BOT_TOKEN=123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

# === OpenAI ===
OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

# === Google Calendar ===
GOOGLE_CLIENT_ID=123456789-xxxxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-xxxxx
GOOGLE_CALENDAR_ID=primary
GOOGLE_REDIRECT_URI=http://localhost

# === Настройки ===
DEFAULT_TIMEZONE=Europe/Moscow
REMINDER_TIME=08:00

# === База данных ===
DATABASE_URL=sqlite+aiosqlite:///bot.db

# === Логи ===
LOG_LEVEL=INFO

# === ВАЖНО: локальный режим ===
OAUTH_MODE=local
```

> ⚠️ **Критичные моменты для новичка:**
> - **Без пробелов** вокруг `=`. Правильно: `BOT_TOKEN=123`. Неправильно: `BOT_TOKEN = 123`.
> - **Без кавычек** вокруг значений. Правильно: `BOT_TOKEN=sk-xxx`. Неправильно: `BOT_TOKEN="sk-xxx"`.
> - `OAUTH_MODE=local` — **обязательно** для запуска без домена.
> - `GOOGLE_REDIRECT_URI=http://localhost` — именно так, без https и без порта.

### 4.3. Сохранить файл

Ctrl+S. Убедитесь, что файл называется именно `.env` (с точкой в начале, без расширения `.txt`).

> 💡 **Частая ошибка:** Windows прячет расширения файлов. Файл может оказаться `.env.txt` — бот его не увидит. В Проводнике: Вид → поставить галочку «Расширения имен файлов», чтобы видеть реально.

## Шаг 6. Подключить Google Calendar (один раз)

Это нужно сделать **один раз** для своего Google-аккаунта.

1. Откройте своего бота в Telegram, нажмите **Start** (или отправьте `/start`)
2. Бот ответит приветствием и пришлёт **ссылку на Google OAuth**
3. **Нажмите на ссылку** → откроется браузер → выберите свой Google-аккаунт → разрешите доступ
4. Браузер попытается открыть `http://localhost/?...` — **страница не загрузится** (это нормально! в local-режиме так и должно быть)
5. **Посмотрите в адресную строку браузера.** Там будет длинный URL вида:
   ```
   http://localhost/?state=abc123&code=4/0AX4Xf-xxxxxxxxxxxxxxxxxxxxx
   ```
6. **Скопируйте часть ПОСЛЕ `code=`** (начинается с `4/`). Например: `4/0AX4Xf-xxxxx`
7. **Отправьте этот код боту в Telegram** (просто вставьте как сообщение)
8. Бот ответит: **«✅ Google Calendar подключён!»**

🏆 **Готово!** Теперь можно тестировать все команды.

> 💡 **Если что-то пошло не так:**
> - Код истёк (был скопирован давно) → отправьте `/start` заново, получите новую ссылку
> - Скопировали лишнее (вместе с `&state=...`) → отправьте `/reconnect` и попробуйте снова, копируя только `4/...`

## 🔑 Получение Google-токенов — ПОДРОБНО

> Это **самая сложная часть** настройки. Разберём её по косточкам: что мы вообще получаем, зачем, и как пройти каждый экран Google без ошибок.
>
> Этот раздел полностью заменяет краткий шаг 2.3 выше — здесь те же действия, но с картинками-описаниями каждого экрана и типовыми ошибками.

### Что мы вообще получаем от Google и зачем

Бот работает с вашим Google Calendar от вашего имени. Чтобы он мог это делать, Google должен **разрешить** ему доступ. Это делается через **OAuth 2.0** — стандартный способ «войти через Google».

В результате вы получаете **4 значения**:

| Значение | Где используется | Пример |
|---|---|---|
| **Client ID** | в `.env` как `GOOGLE_CLIENT_ID` | `123456789-xxxxx.apps.googleusercontent.com` |
| **Client Secret** | в `.env` как `GOOGLE_CLIENT_SECRET` | `GOCSPX-xxxxx` |
| **Authorization code** | одноразовый, отправляется боту в Telegram | `4/0AX4Xf-xxxxx` |
| **Access + Refresh токены** | сохраняются в БД автоматически | — |

> 💡 **Важно понимать разницу:**
> - **Client ID / Secret** — это «паспорт» вашего **приложения** (бота). Вы получаете их один раз и вписываете в `.env`.
> - **Access token** — это «пропуск» в Google Calendar для **конкретного пользователя**. Бот получает его автоматически при подключении и хранит в `bot.db`.
> - **Refresh token** — позволяет боту обновлять просроченный access token без повторного логина. Поэтому подключать календарь нужно **один раз**.

### Какой доступ запрашивает бот

В коде (`app/calendar/auth.py`) запрашивается scope:

```
https://www.googleapis.com/auth/calendar
```

Это **полный доступ на чтение и запись** к вашему Google Calendar. Бот может:
- ✅ создавать, изменять, удалять события
- ✅ читать ваше расписание
- ✅ видеть все ваши календари

Бот **НЕ** получает доступ к почте, дискам, контактам — только Calendar.

### Часть A. Настройка в Google Cloud Console (один раз)

Это нужно сделать **до запуска бота**. Займёт 10–15 минут.

#### A1. Создать проект

1. Откройте [console.cloud.google.com](https://console.cloud.google.com/)
2. В шапке сверху нажмите на выпадающий список проектов → **Новый проект** (NEW PROJECT)
3. Имя проекта: `calendar-bot` (любое)
4. Нажмите **Создать** (Create)
5. Дождитесь создания (10–20 секунд) и убедитесь, что проект выбран в шапке сверху

> 💡 Если у вас уже есть проект — можно использовать его. Но для чистоты эксперимента лучше создать новый.

#### A2. Включить Google Calendar API

1. Левое меню (≡) → **APIs & Services** → **Library**
2. В поиске введите: `Google Calendar API`
3. Откройте найденный результат → нажмите синюю кнопку **ENABLE** (Включить)
4. Дождитесь сообщения «API enabled»

> ⚠️ **Если не включить этот API** — при подключении календаря получите ошибку `Access Not Configured`. Google не даст работать с календарём.

#### A3. Настроить OAuth consent screen («экран согласия»)

Это страница, которую видит пользователь, когда разрешает доступ. Для личного использования — её видите только вы.

1. Левое меню → **APIs & Services** → **OAuth consent screen**
2. **User type**: выберите **External** (Внешний) → нажмите **Create**
3. **Заполните форму (страница OAuth consent screen):**

   | Поле | Что вписать |
   |---|---|
   | App name | `Calendar Bot` |
   | User support email | ваш Gmail |
   | Developer contact information | ваш Gmail (сюда Google шлёт уведомления о проекте) |

4. Прокрутите вниз → **Save and Continue**

5. **Страница Scopes (области доступа):**
   - Нажмите **Add or Remove Scopes**
   - Вручную добавьте: `https://www.googleapis.com/auth/calendar`
     (или найдите в списке «Google Calendar API» → выберите `.../auth/calendar`)
   - Нажмите **Update** → **Save and Continue**

6. **Страница Test users (тестовые пользователи):**
   - ⚠️ **Это критически важно!** Пока приложение в статусе Testing, доступ есть **только** у аккаунтов из этого списка
   - Нажмите **+ Add Users**
   - Введите **свой Gmail** (тот же, где у вас календарь)
   - Нажмите **Add** → **Save and Continue**

7. Проверьте summary → **Back to Dashboard**

> ⚠️ **Частая ошибка:** не добавили себя в Test users → при логине Google выдаёт **`Error 403: access_denied`**. Если увидите это — возвращайтесь сюда и добавляйте аккаунт.

#### A4. Создать OAuth Client ID (ключи приложения)

1. Левое меню → **APIs & Services** → **Credentials**
2. Сверху **+ CREATE CREDENTIALS** → **OAuth client ID**
3. **Application type**: `Web application`
4. **Name**: `Calendar Bot Local` (любое понятное имя)
5. ⚠️ **Authorized redirect URIs** — это **ключевое поле**:
   - В разделе **Authorized redirect URIs** нажмите **+ ADD URI**
   - Впишите **ровно** (скопируйте отсюда):
     ```
     http://localhost
     ```
   - **Без** `https`, **без** порта, **без** `/oauth/callback`, **без** слэша в конце

   > ⚠️ **Почему так:** код бота в local-режиме использует `redirect_uri="http://localhost"` (см. `app/main.py:176`). Значение здесь **должно совпадать символ в символ** с `GOOGLE_REDIRECT_URI` в `.env`. Иначе — ошибка `redirect_uri_mismatch`.

6. Нажмите **Create**
7. 🎉 Появится модальное окно с двумя значениями:

   ```
   Your Client ID
   123456789-xxxxx.apps.googleusercontent.com

   Your Client Secret
   GOCSPX-xxxxx
   ```

8. **Скопируйте оба значения** и сохраните в надёжное место (например, в `keys.txt` на рабочем столе)

> 💡 Эти значения можно посмотреть позже: Credentials → ваш client → карандаш (Edit). Client Secret там виден всегда, а Client ID — в самом начале списка.

#### A5. Вписать ключи в `.env`

Откройте `.env` и замените заглушки на реальные значения:

```env
GOOGLE_CLIENT_ID=123456789-xxxxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-xxxxx
GOOGLE_CALENDAR_ID=primary
GOOGLE_REDIRECT_URI=http://localhost
```

**Проверьте ещё раз:**
- ✅ Нет пробелов вокруг `=`
- ✅ Нет кавычек
- ✅ `GOOGLE_REDIRECT_URI=http://localhost` (точно как в A4, шаг 5)

### Часть B. Прохождение OAuth flow в боте (один раз на пользователя)

Это делается **после запуска бота** (`python -m app.main` или `py -3 -m app.main`).

#### B1. Получить ссылку на авторизацию

1. В Telegram отправьте боту `/start`
2. Бот ответит приветствием и пришлёт **длинную ссылку** вида:
   ```
   https://accounts.google.com/o/oauth2/auth?response_type=code&client_id=123...&redirect_uri=http...&scope=https.../auth/calendar&access_type=offline&prompt=consent&state=AbCdEf...
   ```
3. Нажмите на ссылку — откроется браузер

> 💡 Ссылка содержит параметр `state=...` — это **одноразовый ключ** (nonce), привязанный к вашему `chat_id`. Он действует **10 минут** (см. `app/calendar/oauth_state.py`). Если не успели — отправьте `/start` снова.

#### B2. Разрешить доступ в Google

1. В браузере выберите свой Google-аккаунт
2. ⚠️ Google покажет предупреждение **«Google hasn't verified this app»** (Это приложение не прошло проверку)
   - Это **нормально** для testing-приложений
   - Нажмите **Advanced** (Дополнительно) → **Go to Calendar Bot (unsafe)**
3. Появится экран «Calendar Bot requests access to your Google Account»:
   - Разрешение: **See, edit, share, and permanently delete all the calendars you can access**
   - Нажмите **Continue** (Продолжить)

> ⚠️ Если здесь выдаёт **`access_denied`** — вы не добавили себя в Test users (см. A3, шаг 6).

#### B3. Получить authorization code

4. После «Продолжить» браузер попытается открыть:
   ```
   http://localhost/?state=AbCdEf...&code=4/0AX4Xf-xxxxx...
   ```
5. ⚠️ **Страница НЕ загрузится** (в браузере будет «Не удалось открыть страницу» / ERR_CONNECTION_REFUSED)
   - **Это нормально!** В local-режиме бот не запускает HTTP-сервер
   - **Не закрывайте вкладку** — нужная информация в адресной строке
6. Посмотрите в **адресную строку** браузера — там длинный URL
7. Найдите в нём часть **после `code=`** — она начинается с `4/`:
   ```
   ...&code=4/0AX4Xf-wxxxxxxxxxxxxxxxxxxxxxxxxx
   ```
8. **Скопируйте ТОЛЬКО эту часть** — от `4/` и до конца URL
   - ✅ Правильно: `4/0AX4Xf-wxxxxxxxxxxxxxxxxxxxxxxxxx`
   - ❌ Неправильно: `code=4/0AX4Xf-...`
   - ❌ Неправильно: `state=AbCdEf...&code=4/0AX4Xf-...`
   - ❌ Неправильно: `http://localhost/?code=4/0AX4Xf-...`

> 💡 **Лайфхак для уверенных:** можно скопировать весь URL и вставить в любом онлайн «URL parser» — он покажет параметр `code` отдельно.

#### B4. Отправить код боту

9. Вернитесь в Telegram
10. Просто **вставьте код как обычное сообщение** и отправьте
11. Бот ответит:
    ```
    ✅ Google Calendar успешно подключён!

    Теперь вы можете отправлять мне голосовые и текстовые команды.

    /help — справка
    ```

🏆 **Готово!** Токен сохранён в `bot.db`. Бот теперь имеет полный доступ к вашему Google Calendar и может обновлять токен автоматически.

### Часть C. Что происходит «под капотом»

Чтобы понимать, как это работает (и легче чинить проблемы):

```
[Вы в Telegram]                    [Бот]                         [Google]
     │                               │                              │
  /start ──────────────────────────► │                              │
     │                               │ create_state(chat_id) → nonce│
     │                               │ authorization_url(...) ─────►│
     │ ◄──── ссылка с state=nonce ───┤                              │
     │                               │                              │
  клик по ссылке ──────────────────────────────────────────────────►│
     │                               │              [логин +同意]    │
     │                               │ ◄────── redirect на localhost │
     │                               │     ?code=4/...&state=nonce   │
     │                               │                              │
     │  (страница не грузится,       │                              │
     │   но URL видно в браузере)    │                              │
     │                               │                              │
  отправляете код 4/... ──────────► │                              │
     │                               │ resolve_state(nonce) → chat  │
     │                               │ fetch_token(code) ──────────►│
     │                               │ ◄──── access + refresh token │
     │                               │ save в БД                    │
     │ ◄──── «✅ подключено» ────────┤                              │
```

**Ключевые моменты безопасности (как сделано в коде):**
1. `state` — это случайный 32-байтный nonce (`secrets.token_urlsafe(32)`), не `chat_id`. Подменить нельзя.
2. Nonce **одноразовый** — после использования удаляется (`app/calendar/oauth_state.py`).
3. Nonce живёт **10 минут** (`_TTL_SECONDS = 600`). Потом протухает.
4. Client ID/Secret **не хранятся в БД** — только в `.env`, берутся из settings при каждом обращении (`app/calendar/auth.py:204`).

### Часть D. Типовые ошибки Google OAuth и решения

| Ошибка | Причина | Решение |
|---|---|---|
| **`redirect_uri_mismatch`** | В Google Console redirect URI ≠ `GOOGLE_REDIRECT_URI` в `.env` | Поставьте **ровно** `http://localhost` и в Console (A4), и в `.env` |
| **`access_denied`** (403) | Не добавили себя в Test users | A3, шаг 6 — добавьте свой Gmail |
| **`invalid_client`** | Неправильный Client ID или Secret | Перепроверьте копирование из Console (A4) |
| **`invalid_grant`** | Код уже использован или истёк | Код одноразовый, живёт ~10 мин. Запросите новый: `/start` или `/reconnect` |
| **«Google hasn't verified this app»** | Приложение в статусе Testing | Нажмите Advanced → Go to ... (unsafe). Это нормально |
| **Браузер не открывает localhost** | Так и должно быть в local-режиме | Код всё равно виден в адресной строке — скопируйте его (B3) |
| **Бот пишет «Недействительный код»** | Скопировали лишнее (с `code=`, `state=`, полным URL) | Отправьте `/reconnect` и скопируйте только `4/...` |
| **Бот пишет «state истёк»** | Прошло больше 10 минут с `/start` | Отправьте `/start` заново и быстро пройдите flow |
| **`invalid_scope`** | Указан неверный scope | Не чините сами — в коде scope захардкожен правильно (`.../auth/calendar`) |
| **«Calendar Bot requests access» но нет Continue** | Консент-скрин не опубликован | Оставьте в Testing + добавьте себя в Test users — этого достаточно для личного использования |

### Часть E. Как переподключить календарь

Если токен отозвали, истёк refresh, или просто хотите начать заново:

1. В Telegram отправьте `/reconnect`
2. Бот пришлёт новую ссылку
3. Пройдите OAuth flow заново (Часть B)

**Чтобы полностью отозвать доступ у приложения:**
1. Откройте [myaccount.google.com/permissions](https://myaccount.google.com/permissions)
2. Найдите `Calendar Bot` → **Remove access**
3. Теперь бот потерял доступ — `/reconnect` для переподключения

### Часть F. Проверка, что токены действительно сохранены

После успешного подключения можно проверить, что токен в БД:

```bash
py -3 -c "import sqlite3; c=sqlite3.connect('bot.db'); print(c.execute('SELECT user_id, substr(access_token,1,20), refresh_token IS NOT NULL FROM oauth_tokens').fetchall())"
```

Ожидаемый вывод (что-то вроде):
```
[(1, 'ya29.a0AfH6SMBxxx...', True)]
```

- Первое число — `user_id`
- Второе — начало access token (это доказывает, что он есть)
- `True` в конце — **refresh token сохранён** (значит бот сможет обновляться сам)

> ⚠️ Если `refresh_token IS NULL` — это проблема. Бот проработает ~1 час и потеряет доступ. Решение: `/reconnect` + при логине обязательно дойдите до экрана согласия (параметр `prompt=consent` в ссылке гарантирует выдачу refresh token).

## 🧪 Тесты — автоматическая проверка кода

В проекте есть **автоматические тесты** — они проверяют логику бота без обращения к Telegram/OpenAI/Google. Это безопасно и бесплатно (используются «моки» — подделки внешних сервисов).

### Где лежат тесты

```
tests/
├── conftest.py                  # общие тестовые данные (фикстуры)
├── test_llm_parsing.py          # проверка парсинга ответов ИИ
├── test_calendar_parsing.py     # проверка дат, времени, конфликтов
└── test_calendar_service.py     # проверка CRUD (создание/изменение/удаление событий)
```

### Базовая команда — запустить все тесты

В папке проекта:

```bash
pytest
```

Успешный результат:
```
========================= test session starts =========================
platform win32 -- Python 3.12.4, pytest-8.0.0
collected 35 items

tests/test_calendar_parsing.py .....                          [ 14%]
tests/test_calendar_service.py ............                  [ 48%]

```

Главное — строчка **`35 passed`** (или любое число + `passed`). Если есть `failed` — что-то сломалось.

### Варианты запуска

```bash
# Подробный вывод (показывает каждый тест по имени):
pytest -v

pytest tests/test_llm_parsing.py -v

pytest -s

# Остановиться на первом же падении:
pytest -x

# Запустить с покрытием кода (какой процент app/ проверен):
pytest --cov=app --cov-report=term-missing

# То же, но с красивым HTML-отчётом:
pytest --cov=app --cov-report=html
# затем откройте htmlcov/index.html в браузере
```

### Что именно проверяют тесты (понятно)

**`test_llm_parsing.py`** — умеет ли код правильно «читать» ответ искусственного интеллекта:
- `test_valid_create_event` — корректно создаётся событие «Встреча» 7 июля 10:00–11:00
- `test_all_day_event` — событие на весь день (без времени) парсится правильно
- `test_recurring_event` — повторяющееся событие («каждый будний день») парсится
- `test_defaults` — если ИИ прислал пустой JSON, нет ошибки (есть значения по умолчанию)

**`test_calendar_parsing.py`** — корректность дат, времени и конфликтов:
- `test_valid_date` / `test_invalid_date_*` — что считается правильной датой (`2026-07-04` ✓), а что нет (`tomorrow` ✗)
- `test_conflict_detected` — если в 9:00–9:30 уже есть «Стендап», а мы создаём на 9:15–9:45 → обнаруживается конфликт
- `test_all_day_events_skipped` — события на весь день не считаются «пересечением» по времени

**`test_calendar_service.py`** — реальные операции с календарём (через подделку Google API):
- `test_create_timed_event` — создаётся событие с временем
- `test_create_all_day_event` — создаётся событие на весь день
- `test_create_with_recurrence` — создаётся повторяющееся событие
- `test_delete_event` / `test_update_title` — удаление и изменение названия
- `test_create_invalid_date` / `test_update_empty_id` — ошибки обрабатываются корректно

> 💡 **Тесты не требуют** ни Telegram, ни OpenAI, ни Google — они запустятся сразу после `pip install`. Это первый шаг после клонирования репозитория, чтобы убедиться, что код не сломан.

## 🛠 Частые проблемы и решения

### «ModuleNotFoundError: No module named 'app'»

**Причина:** вы запускаете не из папки проекта.
**Решение:** `cd` в папку `google-calendar-whisper` и проверьте, что там лежит `app/main.py`.

### «ValidationError» / «BOT_TOKEN field required» при запуске

**Причина:** бот не видит файл `.env` или он назван `.env.txt`.
**Решение:**
1. Убедитесь, что файл называется ровно `.env`
2. Проверьте, что в нём есть `BOT_TOKEN=...`
3. Запустите из той же папки

### «pydantic_core._pydantic_core.ValidationError» с упоминанием какой-то переменной

**Причина:** в `.env` есть пробелы вокруг `=` или кавычки.
**Решение:** уберите пробелы и кавычки, как описано в [Шаге 4](#шаг-4-настроить-файл-env).

### Бот молчит на сообщения

**Причины и решения:**
1. Консоль закрыта → бот остановлен. Запустите `python -m app.main` и не закрывайте.
2. Вы не подключили Google Calendar → отправьте `/start`, пройдите шаг 6.
3. Токен бота неправильный → проверьте `BOT_TOKEN` в `.env`.
4. Не попали в Test users Google OAuth → добавьте свой Gmail в consent screen.

### Whisper возвращает ошибку / не расшифровывает голос

**Причина:** закончились деньги на OpenAI или неверный ключ.
**Решение:** проверьте баланс на platform.openai.com и `OPENAI_API_KEY`.

### «google.auth.exceptions.RefreshTokenError»

**Причина:** доступ к Google Calendar отозван или устарел.
**Решение:** `/reconnect` в боте и пройдите подключение заново.

### «Address already in use» / «Порт занят»

**Причина:** другая программа (или предыдущий запуск бота) заняла порт.
**Решение:** закройте все консоли/редакторы с запущенным ботом. В Windows:
```bash
netstat -ano | findstr :8443
taskkill /PID <найденный_PID> /F
```

### Тесты падают с «ModuleNotFoundError»

**Причина:** dev-зависимости не установлены.
**Решение:**
```bash
pip install -e ".[dev]"
```

### Удалил `bot.db`, бот ругается

Это нормально — при следующем запуске `init_db()` создаст новую базу. Но вам придётся заново пройти `/start` и подключить календарь.
